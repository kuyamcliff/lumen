Equalizer & effects

The controls a desktop player has and a web player usually doesn't: a ten-band equalizer, picture adjustments, audio and subtitle sync, A→B looping, frame stepping, snapshots and a media information panel. All of it is in the player itself — no plugin, no configuration.

Press ? in any player for the keyboard reference, or open the effects example to try everything at once.

The panels are a separate lazily-loaded chunk, stylesheet included. A page that never opens one never downloads any of it.

Equalizer

The ten centre frequencies (60, 170, 310, 600, 1000, 3000, 6000, 12000, 14000 and 16000 Hz) and all eighteen preset curves are the ones VLC ships, running through Web Audio biquad filters.

player.setEqualizerPreset("rock");

player.audio.set({
  preamp: -3,
  bands: [8, 4.8, -5.6, -8, -3.2, 4, 8.8, 11.2, 11.2, 11.2],
});

player.audioEffects;   // { equalizer, preamp, bands, preset, boost, delayMs, stereo, normalize }

Preset ids: flat, classical, club, dance, fullbass, fullbasstreble, fulltreble, headphones, largehall, live, party, pop, reggae, rock, ska, soft, softrock, techno.

Two deliberate differences from VLC

Preamp is re-based. VLC stores each preset's preamp on the 0–20 scale it inherited from Winamp, where 12 means unity. Applying that literally in a browser would add +12 dB to a flat curve and clip everything, so Lumen subtracts flat's 12 from every preset — the same relative relationship, at a level a browser can actually play.

Band width is derived, not fixed. VLC's frequencies aren't evenly spaced: there are three bands crammed between 12 and 16 kHz. A single fixed Q would leave the low bands too narrow and pile the top three on top of each other, so each band's Q comes from the geometric distance to its neighbours.

Audio

player.audio.set({
  boost: 1.8,        // 100%–300%, past what video.volume allows
  delayMs: 200,      // audio plays later, for a track that runs ahead
  stereo: "mono",    // "stereo" | "mono" | "left" | "right" | "swap"
  normalize: true,   // dynamic-range compression, VLC's volume normalizer
});
player.audio.reset();
Audio effects need same-origin media, or the crossorigin attribute. Web Audio silently zeroes cross-origin audio that wasn't fetched with CORS — the graph runs and every sample is zero — and the routing can't be undone once created. Lumen checks before building anything and leaves the effects unavailable rather than muting your video. Read player.audio.isAvailable to know up front.

The graph is built the first time an effect leaves its default. That matters for more than bytes: routing an element through Web Audio is permanent for the life of that element, costs an AudioContext, and ends AirPlay/Remote Playback handoff. A page that never touches an effect pays none of it.

Audio delay only runs in one direction. A DelayNode can hold audio back; nothing can hold back a video element's own rendering, so "audio earlier than video" has no browser equivalent.

Picture

player.setVideoFilters({
  brightness: 1.2,     // 0–2
  contrast: 1.3,       // 0–2
  saturation: 0.15,    // 0–3
  hue: 20,             // -180–180 degrees
  gamma: 1.8,          // 0.1–4
  zoom: 1.4,
  rotation: 90,        // 0 | 90 | 180 | 270
  flipHorizontal: true,
  fit: "fill",         // "fit" | "fill" | "stretch"
  aspectRatio: "4/3",  // or null for the source's own
});

player.filters.rotate();            // a quarter turn, as VLC's `r` does
player.filters.cycleAspectRatio();  // source → 16/9 → 4/3 → 1/1 → …
player.filters.cycleZoom();         // 25% → 50% → 100% → 200% → 400%
player.filters.reset();

All of it is a CSS filter and transform on the video element: it costs nothing until a control moves, runs on the GPU, and never touches the decoded frames. Gamma is the one adjustment CSS has no primitive for, so it goes through a small inline SVG feComponentTransfer filter that is only referenced while gamma is off its default.

Looping, stepping, snapshots, bookmarks

player.cycleAbLoop();                  // A, then B, then clear
player.setAbLoop({ start: 12, end: 18 });
player.abLoop;                         // { start, end } | null

player.stepFrame(1);                   // and -1 to step back
player.frameRate;                      // measured, null until enough frames have shown

await player.saveSnapshot();           // downloads a PNG of the current frame
const blob = await player.snapshot({ type: "image/jpeg", quality: 0.9, width: 1280 });

player.addBookmark("The good bit");
player.bookmarks;                      // [{ time, label }], pinned to the scrub bar
player.removeBookmark(time);

Snapshots re-apply Lumen's own colour adjustments to the canvas, so the saved image matches the picture on screen rather than what the decoder produced. Cross-origin media without CORS can't be read back at all — that case is reported rather than saving a blank frame.

Subtitle timing and formats

player.subtitleOffset = 0.5;   // seconds; positive shows cues later
await player.addSubtitleFile(file);

Browsers load exactly one subtitle format: WebVTT. Everything a viewer actually has — the .srt that came with the file, an .ass from a fansub group, a decade-old .sub — is refused by <track> without explanation. Lumen converts SRT, ASS/SSA, SubViewer and MicroDVD in the browser and feeds the result into the same pipeline external WebVTT uses.

Conversion is text-only: ASS positioning, karaoke timing and drawing commands are dropped, because WebVTT has no equivalent and a garbled override tag on screen is worse than clean text. Italic, bold and underline overrides are translated rather than discarded.

Local files

player.openFiles(fileList);   // videos become the queue; subtitles attach
player.openFile(file);

Drag a video onto the player, or press o. Dropping a movie and its .srt together does the obvious thing. Dropping several videos builds a playlist in natural filename order, so a season folder queues as episodes 1, 2, … 10 rather than 1, 10, 2.

Everything routes through an object URL, which is same-origin and range-capable — exactly what the remuxers and MediaSource want — so a local MKV or AVI takes the same path as a remote one, minus the network.

Media information

player.mediaInfo();
// { container: "Matroska (MKV)", engine: "MKV remux", codecs: "vp09.00.21.08,opus",
//   width: 640, height: 360, frameRate: 60.02, duration: 16.2, bitrateKbps: null,
//   droppedFrames: 3, decodedFrames: 334, bufferAheadSeconds: 10.8,
//   bufferedRanges: [[0, 16.2]], audioTrackCount: 1, textTrackCount: 2,
//   playbackRate: 1, readyState: 4 }

Frame rate is measured from requestVideoFrameCallback — the presentation time of frames the compositor actually showed — because a remuxed stream's container may carry no frame-rate field at all. Bitrate comes from the ABR engine when one is driving playback, and from the browser's decoded-byte counters otherwise.

Resume, repeat and shuffle

player.repeat = "all";   // "off" | "one" | "all"
player.shuffle = true;

Playback position is remembered per file and restored on the next visit, keyed on the URL with its query string stripped so an expiring signed CDN link still matches the same film. Positions under 30 seconds, or within 20 seconds of the end, are ignored — it never hijacks a file that barely started or already finished. Add resume="off" to the element to turn it off.
