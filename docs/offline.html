Offline & PWA

Offline playback is mostly a caching problem. These helpers handle the parts that are easy to get wrong — chiefly byte-range requests, without which seeking breaks.

import { downloadForOffline, isAvailableOffline, removeOffline } from "@lumen/player/offline";

await downloadForOffline("movie.mp4", ({ fraction }) => {
  progressBar.value = fraction ?? 0;
});

await isAvailableOffline("movie.mp4");   // true
await removeOffline("movie.mp4");

The service worker

A cached response alone isn't enough: media elements seek with Range requests and need a 206 with Content-Range back. A plain cache.match() returns the whole file with a 200, and seeking silently breaks.

Lumen ships the worker source that answers ranges correctly:

import { OFFLINE_SERVICE_WORKER } from "@lumen/player/offline";

// Write this to a real file at build time, then:
navigator.serviceWorker.register("/lumen-sw.js");

Quota

downloadForOffline resolves false rather than throwing when caching is unavailable or the quota is exceeded, so an app can offer "save offline" without wrapping every call. Check the budget first if you want to warn ahead of time:

const { quota, usage } = await navigator.storage.estimate();
