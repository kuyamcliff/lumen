Any video format

Lumen identifies a file by its actual bytes, not its extension, and routes it to whatever can play it: straight to the browser when possible, or through a JavaScript demuxer that rebuilds the container as fragmented MP4 for Media Source Extensions. No transcoding, no WASM decoder — the compressed frames are copied across untouched.

Matroska (.mkv)

No browser plays Matroska natively. This one is remuxed to fragmented MP4 on the fly while it downloads.

Progressive MP4

Native playback — the fast path, with no sniffing round trip.

AVI (.avi)

The container the web is usually told to give up on. It isn't the container that's the problem — it's what most AVIs carry inside (MPEG-4 ASP, which no browser decodes). This one holds H.264 and AAC, so it plays: demuxed and rewritten as fragmented MP4, frames copied across untouched.

What happens to a format nobody can decode

When a file genuinely can't be played, the reason names the codec rather than blaming the container — an Xvid AVI reports "MPEG-4 ASP (XVID), which no browser can decode", not "AVI files can't be played". 

player.on("error", ({ code, message }) => {
  if (code === "CONTAINER_UNSUPPORTED") {
    // e.g. "This AVI's video is MPEG-4 ASP (XVID), which no browser
    //       can decode. Converting it to H.264 MP4 will fix it."
    showTranscodePrompt(message);
  }
});
